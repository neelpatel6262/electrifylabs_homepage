**ProductCard Component Features:**
- Reusable component for displaying individual products

**Key Concepts:**
- **Conditional Rendering**: Displaying badges only when `bestSeller` is true

- **Component Composition**: ProductCard used within ProductSection

- **Grid Layout**: Organizing products in structured rows

### 5. ServiceCard Component

The `ServiceCard.jsx` file contains a reusable component that displays individual service information using CSS classes defined in the index.css file.

```jsx
function ServiceCard({ icon, heading, subheading, cardClass, headingClass, subheadingClass }) {
  return (
    <div className={cardClass}>
      <div className="service-icon">
        {icon}
      </div>
      <div className={headingClass}>
        {heading}
      </div>
      <div className={subheadingClass}>
        {subheading}
      </div>
    </div>
  );
}
```

**Key Concepts:**
- **Props**: Data passed from parent to child components
- **CSS Classes**: Using predefined CSS classes for styling
- **Component Reusability**: The same component can be used with different CSS classes

### 6. ServiceSection Component

The `ServiceSection.jsx` file contains the services layout that uses multiple ServiceCards, demonstrating how to create complex UIs from smaller components.

**Key Concepts:**
- **Data Mapping**: Converting an array of service data into JSX elements
- **Component Composition**: Building complex UIs from smaller components
- **Props Passing**: Sending data from parent to child components
- **CSS Layout**: Using CSS classes for positioning, spacing, and styling

## How Components Work Together

1. **App Initialization**: `main.jsx` renders all components in sequence
2. **Sequential Rendering**: Navbar → HeroSection → AboutSection → ServiceSection → ProductSection
3. **Component Composition**: Each section builds upon smaller components
4. **Data Flow**: 
   - ServiceSection maps service data to multiple ServiceCard components
   - ProductSection maps product data to multiple ProductCard components
5. **Asset Integration**: SVG and JPG files are imported and used throughout

### Component Hierarchy:
```
main.jsx
├── Navbar
├── HeroSection
├── AboutSection
├── ServiceSection
│   └── ServiceCard (multiple instances)
├── ProductSection
│   ├── ProductCard (multiple instances - top row)
│   └── ProductCard (multiple instances - bottom row)
└── ServiceCard (standalone instance)
```

### Data Flow:
```
ServiceSection (service data) → ServiceCard (presentation)
ProductSection (product data) → ProductCard (presentation)
```

### Component Props Flow:
```
ServiceSection → {icon, heading, subheading, cardClass} → ServiceCard
ProductSection → {image, name, price, bestSeller} → ProductCard
HeroSection → SVG assets and icon components
AboutSection → Image assets and statistical data
```

## Common Beginner Questions

**Q: How do you handle conditional rendering like the best-seller badges?**
A: Use JavaScript logical operators like `&&` to conditionally render elements. For example: `{bestSeller && <div className="best-seller">best sale</div>}`

**Q: How do you handle naming conflicts when importing similar names?**
A: Use import aliasing with the `as` keyword. For example: `import { Star as StarIcon } from 'lucide-react';`

**Q: What are the advantages of using SVG over other image formats?**
A: SVGs are scalable (maintain quality at any size), have smaller file sizes, and can be styled with CSS. Perfect for icons and simple graphics.

**Q: What are props in React?**
A: Props (short for properties) are how you pass data from parent components to child components. They're read-only and help make components reusable.

**Q: How does the map function work in rendering components?**
A: The map function transforms each item in an array into a JSX element. It's perfect for rendering lists of data like the star ratings in HeroSection or product grids.

**Q: What is the benefit of CSS variables over hardcoded values?**
A: CSS variables provide consistent theming, easier maintenance, and centralized design tokens. Update one value and it changes throughout the entire application.

**Q: How do you organize multiple similar components like ProductCard?**
A: Create a reusable component that accepts props, then map over your data array to generate multiple instances with different data.
